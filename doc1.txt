*nvimpio.txt*          PlatformIO Toolchain Integration & Clangd Optimizer

==============================================================================
NVIM-PIO                                                            *nvimpio*

A high-performance, cross-platform Neovim plugin designed to bridge
PlatformIO toolchains with the `clangd` Language Server smoothly. It handles
asynchronous build environment extractions, synchronizes complex board hardware
macro definitions, and intercepts and corrects non-standard compiler argument
diagnostics on both Windows and Linux driving layers.

                                 🚀 NVIM-PIO 🚀

==============================================================================
CONFIGURATION                                                      *nvimpio-config*

To initialize the plugin, invoke the setup call inside your configuration
scripts frame. This registers the Early Lifecycle Invalidation Seeder hooks
and routes your network stream diagnostic traffic patterns natively.

Minimal Initialization Example:
>lua
  require('nvimpio').setup({
    pio = {
      pio_runtime_dir = '~/.platformio',
      pio_storage_dir = '~/.platformio',
    },
    clangd = {
      support = true,
      install = false,
    },
  })
<

==============================================================================
USER MAPPINGS & COMMANDS                                          *nvimpio-commands*

The plugin exposes an interactive state-machine checkbox picker panel to allow real-
time management of code suppression filters and on-screen linting parameters.

:ClangdFilter                                                        *:ClangdFilter*
     Launches the interactive dropdown selection picker panel window viewport
     inside your current active code buffer view frame.

To bind this menu panel execution loop to a standard editor hotkey layout shortcut,
declare an anonymous empty function wrapper statement block inside your scripts:
>lua
  vim.keymap.set('n', '<leader>pf', function()
    require('nvimpio.clangd.diagnostic').manage_file_diagnostics_interactive()
  end, { silent = true, desc = 'PlatformIO: Manage Code Filters' })
<

==============================================================================
INTERACTIVE VIEW CONTROL                                           *nvimpio-interface*

When you open the `:ClangdFilter` menu checklist row view panel, items will display
with their live status markers:

  `[*] Restore Code:  [no_member]`   ➔ Suppressed warning code (Blocked from view)
  `[ ] Suppress Code: [unused-includes]` ➔ Active diagnostic code (Visible on screen)

- Select any row item to toggle its binary state cleanly in RAM.
- Select `💥 Reset All Filters` to purge all local workspace rules instantly.
- Press `<Esc>` to commit choices, flush variables to disk, and re-lint.

==============================================================================
CORE INFRASTRUCTURE MODULES                                         *nvimpio-modules*

The system separates its file operations routines into three clean execution vectors:

1. SELF-HEALING DATABASE                                        *nvimpio-database*
   Tracks history inside a local `.filter.json` database. If missing on boot, the
   engine force-seeds an empty template structure to shield your setups against early
   lifecycle boot racing condition resets.

2. SPLIT RESPONSE OPTIONS                                       *nvimpio-response*
   Moves massive compiler includes and macros arrays lists out of sight into a separate,
   hidden command-line arguments response file (`.pio/build/clangd_flags.txt`). 
   It references parameters natively using the compiler `@` prefix flag.

3. NETWORKING INTERCEPTORS                                      *nvimpio-intercept*
   A dual-route transport interceptor captures incoming LSP event data payloads. 
    Reroutes and strips cross-compiler options errors (like `-mlongcalls`) at the
   C++ binary layer, while forwarding true source diagnostics to your window layout.

STATUSLINE COMPONENTS                                             *nvimpio-statusline*

Integrate the status string tracking hook natively or via modern custom plugins:

lualine.nvim configuration snippet:
>lua
  sections = {
    lualine_x = {
      function() return require("nvimpio.statusline").get_status_string() end,
      'filetype'
    }
  }
<

Native Neovim statusline string assignment:
>lua
  vim.opt.statusline:append("%{v:lua.require('nvimpio.statusline').get_status_string()}")
<
